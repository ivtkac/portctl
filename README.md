# portctl

CLI-інструмент для розгортання Docker-стеків у Portainer та налаштування проксі-хостів через Nginx Proxy Manager.

## Встановлення

```bash
cargo build --release
# Бінарний файл буде доступний у target/release/portctl
```

## Використання

### 1. Зберегти облікові дані Portainer

Перед першим розгортанням потрібно зберегти облікові дані для Portainer:

```bash
portctl creds set -H 192.168.1.100 -s portainer -u admin -p yourpassword
```

Опціонально можна вказати власний URL:
```bash
portctl creds set -H 192.168.1.100 -s portainer -u admin -p yourpassword --url https://192.168.1.100:9443
```

### 2. Розгорнути стек

Після збереження облікових даних, можна розгорнути стек:

```bash
portctl deploy -H 192.168.1.100 -s wireguard
```

Розгортання кількох стеків одночасно:

```bash
portctl deploy -H 192.168.1.100 -s npm,wireguard
```

### 3. Розгортання з проксі

Щоб автоматично налаштувати проксі-хости в Nginx Proxy Manager:

```bash
# Спочатку розгорніть npm (без проксі)
portctl deploy -H 192.168.1.100 -s npm

# Потім розгорніть інші стеки з проксі
portctl deploy -H 192.168.1.100 -s wireguard --enable-proxy
```

## Команди

### `deploy` — Розгортання стеків

```
portctl deploy [OPTIONS] -s <STACKS>

Обов'язкові аргументи:
  -H, --host <HOST>        IP-адреса або хостнейм сервера
  -s, --stacks <STACKS>    Список шаблонів через кому (напр. npm,wireguard)

Опції:
  -u, --user <USER>               Користувач Portainer (або з env PORTAINER_USER)
  -p, --password <PASSWORD>       Пароль Portainer (або з env PORTAINER_PASSWORD)
      --portainer-port <PORT>     Порт Portainer [за замовчуванням: 9443]
      --endpoint <ENDPOINT>       Ім'я endpoint у Portainer [за замовчуванням: local]
      --enable-proxy              Налаштувати проксі-хости в NPM після розгортання
      --npm-host <HOST>           Хост NPM (якщо відрізняється від --host)
      --npm-port <PORT>           Порт NPM [за замовчуванням: 81]
      --portainer-url <URL>       Повний URL Portainer (замінює host + port)
      --npm-url <URL>             Повний URL NPM (замінює host + port)
      --insecure                  Ігнорувати помилки SSL-сертифікатів
      --template-dir <DIR>        Директорія з compose-файлами [за замовчуванням: compose]
  -v, --verbose                   Детальне логування
      --credentials-file <FILE>   Власний шлях до файлу облікових даних
```

### `creds` — Управління обліковими даними

```bash
# Додати або оновити облікові дані
portctl creds set -H <HOST> -s portainer -u <USER> -p <PASSWORD> [--url <URL>]

# Переглянути всі збережені облікові дані
portctl creds list

# Видалити облікові дані
portctl creds remove -H <HOST> -s <SERVICE>
```

> [!note] Примітка: Вручну керуються лише облікові дані portainer. Облікові дані NPM генеруються автоматично під час розгортання npm-стеку та зберігаються самостійно.

### `list-templates` — Список доступних шаблонів

```bash
portctl list-templates
```

## Автогенерація паролів

Для шаблонів з позначкою `$auto` у налаштуваннях паролів — паролі генеруються автоматично при першому розгортанні та зберігаються у файлі з кредами. При повторному розгортанні використовуються вже збережені паролі.

## Файл з кредами

За замовчуванням зберігається у ~/.local/state/portctl/credentials.toml.
Формат файлу:

```toml
[hosts.192.168.1.100.portainer]
user     = "admin"
password = "yourpassword"
url      = "https://192.168.1.100:9443"

[hosts.192.168.1.100.npm]
user     = "admin@mail.com"
password = "autogenerated_password"
```
